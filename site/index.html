Distributed Training Demo

One training loop, four ways to split it across processes. Set one flag — --strategy to single, ddp, fsdp or pipeline — and the same transformer trains the same way, to the same numbers.

How each strategy splits the work

Pick a strategy and press play. Each column is one process (a “rank”). The bars are the model’s layers; the squares underneath are the rows of the batch.

Single

One process holds the whole model and the whole batch. The reference every other strategy must match.

DDP — data parallel

Every rank holds a full copy of the model and trains on its slice of the batch. Gradients are averaged with an all-reduce, so all copies take the same step.

FSDP — fully sharded

Like DDP, but each rank stores only 1/W of the weights, gradients and optimizer state. Layers are gathered just in time and freed after use.

Pipeline

The layers are cut into consecutive stages, one per rank. Microbatches flow through like an assembly line; idle slots at the start and end are the “bubble”.

Run it yourself

# setup (CPU is fine)
uv venv -p 3.11 .venv
uv pip install -p .venv/bin/python torch "numpy<2" pytest
# same loop, four strategies
.venv/bin/python -m disttrain.train --strategy single
.venv/bin/torchrun --nproc-per-node 4 -m disttrain.train --strategy ddp
.venv/bin/torchrun --nproc-per-node 4 -m disttrain.train --strategy fsdp
.venv/bin/torchrun --nproc-per-node 4 -m disttrain.train --strategy pipeline

On machines with NVIDIA GPUs the same commands pick NCCL and one GPU per process automatically. Add --nnodes and --rdzv-endpoint to torchrun to span machines.
